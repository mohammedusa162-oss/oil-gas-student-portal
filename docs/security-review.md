# مراجعة أمنية — بوابة الطالب (الويب + تغليف Android)

تاريخ المراجعة: 2026-10-30 · النطاق: الكود المصدر، حزمة الإنتاج المبنية، وملف Android، وسجل Git.

**طريقة المراجعة:** فحص ساكن (static) بالأدوات المتاحة: قراءة الكود، بحث أنماط (XSS sinks, secrets, links)، `pnpm audit`, فحص محتويات `dist/public` المبني، فحص `AndroidManifest` وملفات الموارد، وفحص 30 التزاماً في سجل Git. مهارة Claude Security الموصوفة في حسابك تعتمد على أدوات plugin (`Workflow` / agent scan) **غير متوفرة في هذا العميل**، لذا لم أشغّلها وسأصرّح بذلك بدلاً من ادعاء فحص لم يحدث.

**ما لم يُفحص (حدود المراجعة):** لا اختبار ديناميكي على جهاز حقيقي، لا اختبار اختراق فعلي، لا فحص إصدارات المكتبات عبر مسارات لا أستخدمها المشروع، ولا فحص لمنصة Play نفسها.

---

## الخلاصة

التطبيق **آمن للاستخدام والنشر** بقدر ما يظهر الفحص الساكن: لا خادم، لا حسابات، لا مفاتيح في الواجهة، لا فتحات XSS، ولا سرّ في السجل. أخطر ما وجدته لا يمسّ المستخدم النهائي بل **مكتبات الخادم غير المنشورة**، وثلاث نقاط تُحسَّن بتعديلات صغيرة.

## النتائج

### F1 — النسخ الاحتياطي الأندرويد يخرج بياناتك «من الجهاز» (متوسط، تناقض مع سياسة الخصوصية)

- **الدليل:** `android/app/src/main/AndroidManifest.xml` → `android:allowBackup="true"` (افتراضي Capacitor).
- **التأثير:** بيانات `localStorage` (اسم الطالب + المواد المكتملة) تدخل تلقائياً في **Android Auto Backup** وتُرفع إلى حساب Google الخاص بالمستخدم. سياسة الخصوصية تقول حرفياً: «لا يغادر جهازك».
- **التقييم:** ليس ثغرة اختراق (النسخة مشفّرة وحساب صاحب الجهاز)، لكنه **عدم دقة في إفصاح Play** وفي سياسة الخصوصية، وكلاهما مطلوب صراحة في Play Console.
- **العلاج (اختر واحداً):**
  - **أ — التعليق:** أبقِ النسخ الاحتياطي وارحّم في سياسة الخصوصية جدولاً: «قد تنسخ خدمات Android النظامية هذه البيانات إلى نسخة احتياطية لحسابك في Google (نسخ Android Auto Backup) ويمكنك تعطيلها من إعدادات النظام».
  - **ب — الإيقاف:** `android:allowBackup="false"` لتبقى العبارة صادقة 100%. الطالب يخسر استعادة تقدمه عند تغيير الهاتف.

### F2 — FileProvider يمنح الوصول لمساحة التخزين الخارجية كاملة (منخفض/متوسط)

- **الدليل:** `android/app/src/main/res/xml/file_paths.xml` → `<external-path name="my_images" path="." />`
- **التأثير:** أي ملف يُصدَّر عبر `FileProvider` يمكن أن يكون خارج حدود التطبيق (`path="."` = كل التخزين الخارجي). التطبيق حالياً **لا يستخدم** `FileProvider` (الطباعة عبر `window.print`)، فالمخاطرة سطحية لا استغلال.
- **العلاج:** استبدل المسار بمجلد محدّد (مثل `files/` و`cache/`) أو احذف `external-path` إن لم يُستخدم أي مشاركة ملفات.

### F3 — 10 ثغرات في الاعتماديات: حرجة واحدة وثلاث عالية — لكنها ليست داخل التطبيق (متوسط لبقية النشر)

```
CRITICAL proxy-addr   — تزوير IP عبر IPv4-mapped IPv6
HIGH     path-to-regexp — ReDoS
HIGH     body-parser   — DoS
HIGH     zod           — استنزاف ذاكرة عند تحقق من مدخلات ضخمة
MODERATE qs (×4) · LOW qs/body-parser (×2)
```

- **الدليل المهم:** تحققتُ أن **لا واحدة منها داخل الحزمة المنشورة**: `express: 0 hits`, `body-parser: 0`, `qs: 0`, `path-to-regexp: 0`, `proxy-addr: 0` في `dist/public/assets/*.js`، و`zod` لا يُستورد من `client/src` إطلاقاً.
- **المسار الحقيقي:** كلها تابعة لـ `server/index.ts` (Express) — أي مكتبات خادم محلي فقط، **ولا يدخل تطبيق Android ولا موقع Pages**.
- **العلاج:** إما `pnpm update express body-parser qs path-to-regexp proxy-addr zod` (رفع الإصدارات المصلَّحة)، أو **حذف `express` كلياً** لأنه يقدّم ملفات ثابتة فقط ويُعاد بناؤه في Pages بأمر آخر — وأخفّ امتلاكًا لسطح الهجوم. **إن لم تكن تعرض الخادم للإنترنت يوماً فالمخاطرة عندك = صفر**، وإن كنت تنوي تشغيله فاحترجه قبل النشر.

### F4 — لا توجد سياسة أمان محتوى (CSP) (منخفض)

- **الدليل:** `dist/public/index.html` → `has CSP meta: false`، وفيه سكربت inline (`window.__MANUS_HOST_DEV__…`) فالسياسة الصارمة ستحتاج تجزئة/nonce.
- **التأثير:** الواجهة لا تعرض محتوى من مستخدمين ولا `dangerouslySetInnerHTML` (تحققت: **0 نتيجة**)، فالخطر عملي منخفض؛ ومع ذلك فإن أي XSS لاحق سيتعرّض لتنزيل سكربتات خارجية بلا حاجز.
- **العلاج:** أضف في `client/index.html`:
  `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; base-uri 'none'; object-src 'none'; frame-ancestors 'none'; form-action 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'">`
  (لا تُدرج قيود `script-src` إلا مع إزالة السكربتات الـ inline أعلاه).

### F5 — إصدار الإصدار بلا ضغط ولا إخفاء (منخفض)

- **الدليل:** `android/app/build.gradle` → `minifyEnabled false`، ولا `shrinkResources`.
- **التأثير:** حجم أكبر قليلاً وكود غير مموَّه. لا أسرار في الكود، فالخطر محدود — لكن R8 يقلّل مساحة الأخطاء ويطوّي الكود.
- **العلاج:** `minifyEnabled true` + `shrinkResources true` ثم اختبار الطباعة/PDF بعد البناء.

### F6 — كود ميت يحمل مفاتيح بيئية إن ضُبطت يوماً (معلومة)

- `client/src/const.ts` → `getLoginUrl()` يبني رابط OAuth تجريبي (`VITE_OAUTH_PORTAL_URL`, `VITE_APP_ID`, `/api/oauth/callback`) **ولا يُستدعى من أي مكان**، ولا يوجد خادم لاستقبال الـ callback.
- `client/src/components/Map.tsx` → `VITE_FRONTEND_FORGE_API_KEY` **غير مستورد** (استخدمتُ أيقونة `Map` من lucide فقط).
- **تحذير:** متغيّرات `VITE_*` تُدمج في الحزمة **وتصبح عامة دائماً**. إن ضبطتَ أي منها لاحقاً فقد تنشر مفتاحاً دون قصد.
- **العلاج:** احذف المسارين الميتين إن لم تكن تخطط لهما، وضع علامة في README إن أبقيتهما.

### F7 — بيانات بلا تشفير في `localStorage` (منخفض / مقبول)

- **الدليل:** المخزَّن = اسم الطالب (≤80 حرفاً)، معرّفات المواد المكتملة، اختيار التقرير — بلا كلمات مرور ولا بيانات حساسة.
- **العرض:** أي من يصل لملف النظام (جهاز مكسور/متجذر) يقرأها. مع F1 يصبح العرض = نسخة Google الاحتياطية.
- **الحكم:** مقبول لطبيعة البيانات، ويكفي فتح قفل الشاشة على الجهاز. لو زدتَ بيانات أدقّ لاحقاً ففكّر في تشفير التخزين (Android Keystore/EncryptedSharedPreferences).

## ما تحقّقت منه ووجدته سليماً

| البند | النتيجة |
|---|---|
| فتحات XSS | **0** — لا `dangerouslySetInnerHTML` ولا تعيين `innerHTML` في `client/src` |
| سرّ في سجل Git | **لا شيء** — فحصت 30 التزاماً عن نمط `PRIVATE KEY`/`storePassword=`/مفاتيح → صفر |
| ملفات `.env` | **غير متتبَّعة** (`git ls-files` فارغ) |
| مفتاح التوقيع | مستبعد بقواعد `.gitignore` في المستودعين ✓ |
| روابط خارجية | **3/3** بها `rel="noopener noreferrer"` مع `target="_blank"` ✓ |
| النقل عبر HTTP | محظور افتراضياً (`targetSdk 36` بلا `usesCleartextTraffic`) ✓ |
| WebView | `allowMixedContent: false`، `webContentsDebuggingEnabled: false` ✓ |
| الصلاحيات | `INTERNET` فقط — لا موقع ولا كاميرا ولا جهات اتصال ✓ |
| تتبّع/إعلانات/SDK خارجي | لا شيء (أخفّ إمكانية لـ Play Data safety) ✓ |
| إعدادات Play | `targetSdk 36` (شرط 2026-08-31)، توقيع AAB موثّق بالبصمة ✓ |
| نداءات شبكة خارجية في الإنتاج | **صفر** — الخط محلياً، ولا Google Fonts ولا تحليلات |

## ترتيب العمل المقترح

1. **قبل الرفع على Play:** قرّر F1 (إعلان أو إيقاف النسخ الاحتياطي) — فهذا يمسّ إجابتك في نموذج أمان البيانات.
2. **قبل أي نشر للخادم:** حدّث أو احذف Express (F3).
3. أضف CSP (F4) وضيّق FileProvider (F2) في دفعة واحدة، ثم أعد البناء والاختبار.
4. فعّل R8 (F5) مع اختبار الطباعة بعد البناء.

لم أغيّر أي كود كجزء من هذه المراجعة — كل ما سبق مقترحات تنفّذها إن طلبت.
